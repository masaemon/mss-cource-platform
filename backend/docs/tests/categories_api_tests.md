# カテゴリーAPI 統合テストケース

## 1. カテゴリー一覧取得 API (`GET /api/v1/categories`)

### 正常系

#### TC-CATEGORY-001: カテゴリー一覧を取得
- **前提条件**: データベースに5つのカテゴリーが登録済み
- **リクエスト**: `GET /api/v1/categories`
- **期待結果**:
  - ステータスコード: 200
  - レスポンスは配列
  - 件数が5件
  - 各カテゴリーに以下が含まれる:
    - `id`（UUID）
    - `name_ja`（日本語名）
    - `name_en`（英語名）
    - `slug`（URL用スラッグ）

#### TC-CATEGORY-002: name_ja の昇順でソートされる
- **前提条件**: カテゴリーが以下の順で登録:
  - 「ビジネス」
  - 「デザイン」
  - 「プログラミング」
- **期待結果**:
  - レスポンスの順序が「デザイン」「ビジネス」「プログラミング」（name_ja の昇順）

#### TC-CATEGORY-003: 日英両方の名前が含まれる
- **前提条件**: カテゴリー "プログラミング / Programming" が存在
- **期待結果**:
  - `name_ja` = "プログラミング"
  - `name_en` = "Programming"

#### TC-CATEGORY-004: slug が正しく設定されている
- **前提条件**: カテゴリー "プログラミング" のslug = "programming"
- **期待結果**:
  - `slug` = "programming"
  - スラッグは英小文字・ハイフン・数字のみ

#### TC-CATEGORY-005: 未認証でもカテゴリー一覧を取得可能
- **リクエストヘッダー**: なし
- **期待結果**:
  - ステータスコード: 200
  - カテゴリー一覧が取得できる

#### TC-CATEGORY-006: カテゴリーが0件の場合
- **前提条件**: データベースにカテゴリーが0件
- **期待結果**:
  - ステータスコード: 200
  - レスポンス: []（空配列）

#### TC-CATEGORY-007: name_en が null のカテゴリー
- **前提条件**: カテゴリーに name_en が設定されていない
- **期待結果**:
  - `name_en` = null
  - エラーが発生しない

#### TC-CATEGORY-008: 大量のカテゴリー（100件）
- **前提条件**: データベースに100件のカテゴリーが登録済み
- **期待結果**:
  - ステータスコード: 200
  - 件数が100件
  - パフォーマンスが許容範囲内（1秒以内）

### 異常系

現時点では異常系のテストケースはなし（シンプルなGET APIのため）

## 3. フロントエンドでの利用パターン

### 想定される利用シーン

#### TC-CATEGORY-014: コース作成時のカテゴリー選択
- **シナリオ**: 講師がコースを作成する際、カテゴリー一覧から選択
- **期待動作**:
  - カテゴリー一覧を取得
  - ドロップダウンメニューに name_ja を表示
  - 選択したカテゴリーの id をコース作成APIに送信

#### TC-CATEGORY-015: コース一覧のカテゴリーフィルター
- **シナリオ**: ユーザーがカテゴリーでコースを絞り込む
- **期待動作**:
  - カテゴリー一覧を取得
  - フィルターボタンに name_ja を表示
  - 選択したカテゴリーの id を使って `/courses?category={id}` にリクエスト

#### TC-CATEGORY-016: 多言語対応（日本語）
- **シナリオ**: 日本語ロケールのユーザー
- **期待動作**:
  - カテゴリー表示に name_ja を使用
  - 「プログラミング」「デザイン」など

#### TC-CATEGORY-017: 多言語対応（英語）
- **シナリオ**: 英語ロケールのユーザー
- **期待動作**:
  - カテゴリー表示に name_en を使用
  - "Programming", "Design" など

#### TC-CATEGORY-018: URLのスラッグ利用
- **シナリオ**: カテゴリーページのURL
- **期待動作**:
  - `/categories/programming` のような読みやすいURL
  - slug を使ってカテゴリーを特定

## 6. データ整合性テスト

### データベース制約

#### TC-CATEGORY-026: slug のユニーク制約
- **前提条件**: データベースに slug = "programming" が存在
- **期待動作**: 同じ slug のカテゴリーは挿入できない（UNIQUE制約）

#### TC-CATEGORY-027: name_ja の NOT NULL 制約
- **期待動作**: name_ja が null のカテゴリーは挿入できない

#### TC-CATEGORY-028: slug の NOT NULL 制約
- **期待動作**: slug が null のカテゴリーは挿入できない

#### TC-CATEGORY-029: 外部キー制約（コースからの参照）
- **前提条件**: カテゴリーにコースが紐づいている
- **期待動作**:
  - カテゴリー削除時にエラー（外部キー制約違反）
  - または CASCADE でコースのcategory_idがnullになる（設定次第）

## テスト実行時の注意事項

1. **ソート順**: カテゴリー一覧が name_ja の昇順でソートされることを確認する
2. **多言語対応**: name_ja と name_en の両方が正しく返却されることを確認する
3. **slug の形式**: slug が英小文字・ハイフン・数字のみであることを確認する
4. **認証不要**: 未認証でもカテゴリー一覧を取得できることを確認する
5. **NULL処理**: name_en が null でもエラーが発生しないことを確認する
6. **パフォーマンス**: カテゴリー数が増えてもレスポンスタイムが許容範囲内であることを確認する
7. **キャッシュ**: 将来的にキャッシュを実装する場合、更新時にキャッシュがクリアされることを確認する
8. **外部キー**: コースからカテゴリーへの参照が正しく機能することを確認する

## 補足: カテゴリー管理機能（将来実装予定）

現時点ではカテゴリー一覧取得のみ実装されていますが、将来的に以下の機能が必要になる可能性があります:

1. **カテゴリー作成**: 管理者がカテゴリーを追加
2. **カテゴリー更新**: カテゴリー名やスラッグの変更
3. **カテゴリー削除**: 未使用のカテゴリーを削除
4. **カテゴリーの並び替え**: 表示順序の変更（order_number フィールドの追加）
5. **カテゴリーの有効/無効**: 一時的に非表示にする機能

これらの機能のテストケースは、実装時に追加で作成する必要があります。
